# Acadex

Student, Teacher and Admin platform. `web/` is Next.js + Tailwind, `api/` is Express + PostgreSQL + JWT. See `CLAUDE.md` for commands and `.claude/rules/` for the stack rules (slide 10 only).

## Run it

1. PostgreSQL (macOS): `brew install postgresql@16`, then start it with `LC_ALL=en_US.UTF-8 pg_ctl -D /opt/homebrew/var/postgresql@16 -l /opt/homebrew/var/log/postgresql@16.log start` (the `LC_ALL` is needed or it exits immediately; `brew services start postgresql@16` also works). Create the databases once: `createdb acadex && createdb acadex_test`.
2. API: `cd api && cp .env.example .env` (set `JWT_SECRET`), then `npm run migrate && npm run seed && npm run dev`. The seed prints the demo password (or uses `DEMO_PASSWORD`).
3. Web: `cd web && npm install && npm run dev`, open http://localhost:3000 and sign in with a seeded account (`admin@college.edu`, `neha.verma@college.edu`, `rahul.iyer@college.edu` (counsellor), `aarav.sharma@college.edu`).

If the API is not running, the portals fall back to demo data.

Tests: `npm test` runs the whole suite on an in-memory PostgreSQL emulator (no server needed). `npm run test:pg` runs the same suite on the real database in `acadex_test`, each test in its own throwaway schema. Both pass (144 tests).

## Built so far

- Auth: register (students only), login, single-use refresh tokens, logout, `/auth/me`.
- Users: admin lists, creates, edits and disables accounts; teachers can list students.
- Courses: create, edit, delete, assign teacher (admin), enrol/drop (student), roster management (course teacher or admin).
- Attendance: teachers record a session per class date (present / late / absent / excused), edit or delete past sessions; students see their own record and how many classes they need to reach 75%.
- Marks: teachers create assessments (quiz, assignment, midterm, endterm, practical) and enter scores; students see their own scores and overall %.
- Assignments: teachers set work with a due date and maximum marks, students submit text and/or a link (late work is accepted and flagged, resubmission allowed until graded), teachers grade with feedback. Completion and missing work feed the Performance Analyzer. File uploads are not supported yet.
- Faculty Doubt Desk: students ask the teacher of a course they are enrolled in, classmates upvote "same doubt", similar solved doubts are suggested while typing, the course teacher (or an admin) answers, which marks it solved, and every doubt and answer is searchable by the course. Image questions (OCR) are not built yet.
- Smart Notes: students paste notes or load a .txt/.md file; the server builds a key-sentence summary, key terms, practice questions and fill-in-the-blank MCQs, and answers questions by finding the best matching passages in their own notes. This is a built-in text engine (`api/src/notes/text.js`) with no AI model: quality is basic. Notes are private. PDF and image notes, class-shared notes and embeddings (pgvector) are not built yet.
- Study Planner: students add exams (from a course or any subject) with a topic checklist; the server spreads unfinished topics evenly over the days before each exam (`api/src/planner.js`), flags exams needing more than 3 new topics a day, and reschedules as topics are ticked. Planner data is private. No reminders or notifications yet.
- Early Warning: a transparent rule-based risk score (0-100) per student from attendance (35 points), marks (30), overdue assignments (20) and falling marks (15), computed in `api/src/risk.js`. Students see their score, the reasons and alerts; teachers see their class ranked by risk and log actions (mentor call, reminder, counselling referral) with status and outcome; admins see the whole institution. This is a baseline, not the trained model from the deck. No automatic notifications yet.
- Student Help Center: students raise tickets in six categories (fees, hostel, library, IT, certificates, academics); each is routed to a department automatically and urgent wording sets high priority. Admins act as the front desk: re-route, change priority and status, reply in a thread and resolve; a student reply reopens a resolved ticket. Department staff do not have their own logins yet, and there are no email notifications.
- Student Counselling: an admin flags teachers as counsellors (`PATCH /users/:id {isCounsellor: true}`; there is no admin screen for this yet). Counsellors publish time slots; students book one (max 3 upcoming) as academic, career or personal, optionally anonymous (the counsellor sees "Anonymous student" in the app; the database still links the booking to the student). Counsellors confirm, complete or cancel, keep a private note, and leave a follow-up the student can read. No reminders or video links.
- Mentorship: any student can opt in as a mentor with a headline, year, up to 6 topics and a bio, and step down at any time (admins can hide a profile). Juniors search mentors, ask questions (anonymous by default; the mentor sees "Anonymous"), mentors answer from a "Questions for me" tab, and the asker rates each answer 1-5, which builds the mentor's average. Max 10 unanswered questions per student. Mentors are not verified by staff before they appear. Not built: assigning a mentor to an at-risk student (Early Warning), one-to-one chat or session booking.
- Project & Idea Hub: students post ideas (title, description, tech, teammates wanted, preferred teacher mentor); everyone signed in can browse and filter. Others ask to join and the owner accepts or declines within the open spots. A teacher (the named mentor, or any teacher who claims an unassigned idea) approves it, which starts the project, or asks for changes, which the owner fixes and resubmits. The team logs progress updates and a repository link, the mentor leaves feedback, and the owner or mentor marks it completed. Max 5 active projects per student. Not built: file uploads, linking repo activity automatically, project grading.
- Career Guidance: students save skills, interests and (optionally) CGPA; a transparent matcher in `api/src/careers.js` ranks nine career paths (skills 60, interests 30, CGPA fit 10 points), shows the skills they have and the ones to learn, and generates a four-phase, twelve-month roadmap. Courses and internship types are general guidance, not live openings. No job-board or company integration.
- Notifications: events across the modules (new and answered doubts, ticket replies, support actions, counselling, mentorship, project requests and reviews, new and graded assignments, answers on your community post) create in-app notifications shown on the bell, and are also emailed (set `SMTP_URL` in `api/.env`) and pushed to subscribed browsers (set the three `VAPID_*` keys: `npx web-push generate-vapid-keys`). Each user can switch email and push off from the bell. A channel without settings is skipped, and a failing channel never breaks a request. Email goes through nodemailer and is tested against a real local SMTP server; browser push is tested with a fake sender only (a real push needs your VAPID keys and a browser).
- Live dashboards and admin: the student, teacher and admin home pages and the admin Users & roles page now use real data (composed from the existing endpoints), and the sidebar shows the signed-in person. Admins can create accounts, change roles, suspend or reactivate people and choose which teachers are counsellors. The student dashboard no longer shows the fake performance trend or study streak.
- Admin analytics and settings: Module usage (share of students who created or changed something in each module over 7, 30 or 90 days), Departments (live open and resolved tickets and average resolution time for the six fixed departments) and Alert rules (admin-tunable attendance target, marks floor, overdue-assignment cap, marks-drop sensitivity and the medium/high cut-offs for the Early Warning score; saving applies to everyone at once and shows how many students land in each level). Rules are stored in `app_settings`. The fixed 75% / 60% "weak subject" flags elsewhere are not affected. Everything in the three portals now uses real data.
- Class Resources: a course's teacher (or an admin) shares typed notes or links with the class (students are notified); students open them on a new Class Resources page and can add a shared note to their own Smart Notes once, which generates the summary, questions and quiz. Teachers see how many students added each note. Not built: file uploads (PDF, slides, images).
- OCR for image questions: in the Doubt Desk, "Attach a photo of the question" reads the text from a PNG, JPEG, WebP or BMP (up to 5 MB) with tesseract.js and fills the title and details for the student to check and edit before sending. The image is checked by its bytes and is not stored. The first use downloads about 10 MB of English language data (cached in `api/.ocr-cache`), so the server needs internet once. English printed text works best; handwriting is unreliable. `RUN_OCR_TEST=1 npm test` also runs a real-OCR test.
- File uploads: students attach up to 3 files to an assignment submission and teachers share files with a class. Allowed: PDF, PNG, JPG, WebP, DOCX, PPTX, XLSX, TXT, MD, CSV, up to 10 MB each, judged by the file's bytes (HTML, SVG, scripts and executables are refused). Files are stored on disk in `api/uploads` (set `UPLOAD_DIR`; back it up) under random names, downloaded only by people who may see what they are attached to, with `nosniff` and attachment headers. Each user is capped at 100 files / 200 MB, and uploads never attached to anything are deleted after 24 hours. No virus scanning and no in-browser preview yet.
- Redis (optional): set `REDIS_URL` and rate limits are counted in Redis (shared across API processes, kept over restarts) and the admin usage and risk overviews are cached for 30-60 seconds. Without Redis, or if it is down, everything still works in memory. Install with `brew install redis`.
- Risk Monitoring: the admin page that used to show fake model metrics now shows the live score distribution, what is driving risk, how much support got a response and the rules in use. It says plainly that the trained model is not deployed.
- Student Community (ported from the Django service): rooms, posts, answers, comments, votes, reports and teacher moderation under `/api/v1/community`. Every course gets a members-only room (teacher plus enrolled students, kept in sync with enrolment). File attachments, notifications and full-text search are not ported yet.
- Web: real login, My Courses / My Classes / Courses, Attendance and Marks (teacher), Attendance & Marks (student), plus live Performance Analyzer (student) and Class Performance (teacher). Every other page is still mock data.

Percentages: assignment completion is submitted over assignments that are past due or already handed in. Attendance counts present and late, ignores excused; marks are total score over total maximum of graded work. "Weak" means attendance under 75% or marks under 60%. All of this lives in `api/src/stats.js`.

## Not built

- Vector search / embeddings for Smart Notes (needs an embedding model; the built-in text search is used instead).
- The trained machine-learning risk model from the deck (an offline pipeline; a transparent rule-based score is used).
- Real browser push delivery and antivirus scanning of uploads.
- Pushing to GitHub is up to you.
